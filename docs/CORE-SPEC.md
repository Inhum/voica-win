# Voica — Core Spec (кросс-платформенная спека поведения)

Канонический документ поведения Voica, **общий для всех платформ**. Референс-реализация —
macOS (`Inhum/voica`, Swift/AppKit). Порт под Windows (`Inhum/voica-win`, C#/.NET WPF) обязан
воспроизводить это поведение; платформенные отличия (UI-фреймворк, системные API, дефолты
хоткея, пути хранения) явно отмечены.

**Правило паритета:** добавил/изменил фичу в одной ОС → сначала правишь эту спеку, потом
зеркалишь во вторую реализацию. Матрица паритета — в конце файла.

---

## 1. Суть приложения

Фоновое приложение в трее/меню-баре для macOS и Windows. По глобальному хоткею записывает
речь с микрофона, распознаёт её **с пунктуацией** и вставляет текст в активное поле (или
показывает в окне). Движок распознавания — на выбор: **облако** (Groq Whisper, BYO-key) или
**локальный офлайн** (на устройстве, без сети и ключа; платформо-специфично, см. §2.5).

## 2. Groq Speech-to-Text (контракт запроса)

- **Endpoint:** `POST https://api.groq.com/openai/v1/audio/transcriptions`
- **Модель:** выбирается пользователем (Настройки → Dictation), по умолчанию
  `whisper-large-v3-turbo`. Предлагаем `whisper-large-v3-turbo` (быстрее) и
  `whisper-large-v3` (точнее); список фиксирован (не динамика — STT-модели у Groq стабильны,
  а их немного). Сохраняется в `Prefs.sttModel`, невалидное значение откатывается на дефолт.
- **Auth:** заголовок `Authorization: Bearer <key>`
- **Тело:** `multipart/form-data`, поля:
  - `file` — аудиофайл записи (см. §3)
  - `model` = `Prefs.sttModel`
  - `response_format` = `verbose_json` (даёт `text` + `language` + `duration`)
  - `temperature` = `0`
  - `prompt` = словарь терминов (**только если непустой**, см. §6)
  - `language` — выбирается пользователем (Настройки → Dictation), по умолчанию **"auto"**:
    при "auto" поле **не задаём** (Whisper определяет сам; важно для смеси рус+англ), иначе
    форсируем ISO-639-1 (`ru`/`en` — помогает коротким фразам с ошибочным авто-детектом).
    Только облако: локальный движок (GigaAM) — русскоязычный, настройку игнорирует.
    **Список из трёх пунктов — не перечень поддерживаемых языков.** Whisper понимает около сотни
    языков, и все они работают через "auto"; ru/en вынесены отдельно лишь потому, что это наша
    частая смесь, а форсирование лечит короткие фразы с ошибочным авто-детектом. Подсказка под
    выбором обязана это проговаривать: иначе три пункта читаются как «приложение знает два
    языка». Расширять список под гипотетического пользователя не нужно — при реальном запросе
    добавлять сразу весь список Whisper, а не спорить, какие языки достойны.
- **Ответ (200):** JSON с полями `text` (обязателен), `language`, `duration`. `text` тримить.
- **Таймаут:** 120 c.
- **Ошибки → сообщения пользователю:** 401 «ключ отклонён, проверь в Настройках»,
  413 «запись слишком длинная, разбей», 429 «лимит Groq, подожди», прочее «Groq вернул N: …»
  (тело обрезать до ~200 симв). Сетевые ошибки — показать текст ошибки.

### Валидация ключа
- `GET https://api.groq.com/openai/v1/models` с `Authorization: Bearer <key>`, таймаут 20 c.
- 200 → ключ рабочий; 401 → отклонён; иначе → `HTTP N`.

## 2.5. Локальный офлайн-движок распознавания (опциональный, платформо-специфично)

Альтернатива облаку: распознавание целиком **на устройстве**, без интернета и без ключа Groq.
Реализация зависит от платформы (нет общего кросс-платформенного рантайма), поэтому это
**намеренное платформенное отличие** 🔀; общими остаются лишь UX-принципы ниже.

- **Переключатель движка** «Облако (Groq) / Локально (офлайн)» в Настройках (раздел General),
  по умолчанию **облако**. Ключ Groq для локального движка не требуется (онбординг его не
  навязывает, если выбран локальный).
- **Модель качается по требованию**: индикатор прогресса, проверка **SHA-256**, распакованная
  модель — вне бандла (рядом с историей, `…/models/`). Пока качается — работает облако.
  ⚠️ **Выбран локальный движок, а модели нет — облаком НЕ подменяем ни при каких условиях,
  включая «пока качается».** «Локально (офлайн)» — обещание приватности, и тихо нарушить его
  хуже, чем отказать; нажатие «Скачать модель» согласия отправить голос наружу не означает.
  Поймано живой проверкой на macOS 0.9.19: после удаления модели диктовка ушла в Groq, и в
  истории осталось `whisper-large-v3`, хотя переключатель показывал офлайн. Дыра открылась,
  когда скачивание перестало начинаться само (§9.5), — до этого состояние было почти недостижимо.
  ⚠️ **Предупреждение показывается НА СТАРТЕ диктовки, а не после неё.** Сказать «модели нет»
  человеку, который уже наговорил две минуты, — потратить его время впустую: расшифровать эту
  запись нечем. Текст называет, чего не хватает («Скачайте локальную модель GigaAM»), и даёт
  кнопку прямо на вкладку с переключателем движка и кнопкой загрузки. Проверка на выдаче
  остаётся подстраховкой на случай, когда модель удалили уже во время записи. Удаление модели — в разделе Data (освобождает место; облако
  продолжает работать, докачать можно снова).
- **Обработка — по целому файлу**, как и облако (§3): пишем всю запись, затем распознаём
  разом. **Не** потоковое realtime-распознавание, без VAD. Длинные записи **чанкуем окнами
  ~25с с небольшим нахлёстом (~2с)**; на стыке дубль убираем по совпадению слов (без учёта
  регистра/пунктуации), иначе — соединение через пробел. Без нахлёста слово/пунктуация на
  границе куска терялись или двоились.
  ⚠️ **Сравнение слов на стыке обязано быть терпимым (macOS 0.9.15).** Точное совпадение НЕ
  работает: у соседних окон разный контекст, и одно и то же слово они пишут по-разному —
  тогда нахлёст не находится, а **обе копии уезжают в текст**. Настоящие примеры из длинной
  диктовки: «руководителя одного отдела, руководителя другого отдела **… одного отдела,
  руководитель другого отдела** приходилось…» и «…из чего вообще строить, из кип.. **Может
  быть, из чего вообще строить, из** кирпича…». Правило:
  - Слова считаются одним и тем же, если совпали целиком **либо расходятся только хвостом**
    (общий префикс ≥ 80 % длины большего). Так ловятся окончания: «руководителя» /
    «руководитель». Слова короче 6 символов сравниваются ТОЛЬКО точно, иначе «стол»
    склеится со «стоп».
  - Если нахлёст не нашёлся вовсе — **повторить поиск без последнего слова первого куска**:
    окно часто обрывает слово на полуслове («из кип» вместо «из кирпича»), и такой огрызок
    не похож ни на что, ломая сравнение всего окна. Нашёлся так — огрызок выбросить: целое
    слово есть в следующем куске.
  - **Ряд от четырёх слов прощает ОДНО расхождение.** Иначе одно слово рушит весь ряд: живой
    случай — «управляющий» против «управляющего», 9 общих букв из 12, это 0.75 при пороге 0.8,
    и фраза уехала в текст дважды. Порог при этом НЕ трогаем: подкрутить его до 0.75 значило бы
    подогнать под один случай (запрещено §6.2) — правило нужно структурное.
    ⚠️ **Прощённое слово никогда не может быть последним в ряду.** Расхождение на самом стыке —
    это обычно обрубок, обрезанный окном («из кип» вместо «из кирпича»); его надо не прощать,
    а ронять откатом выше, иначе обрубок останется в тексте, а целое слово потеряется.
  - **Ничего не нашлось пословно — сравнить СКЛЕЙКИ без пробелов** (macOS 0.9.17). Окна умеют
    разбивать одно и то же место на РАЗНОЕ число слов, и тогда выравнивание слово-в-слово
    ломается в принципе: живые случаи — «3кар» против «Три кар» (четыре слова против пяти) и
    «она Неинтересно. Но когда я е написал, она» против «она». Ищем самую длинную пару
    «j слов с конца первого куска, k слов с начала второго», похожую выше 0.8.
    ⚠️ **Только запасным путём, после пословного сравнения**: склейки сравниваются заметно
    свободнее, и пускать их первыми — значит рисковать съесть лишнее. Минимум **10 символов**
    оттуда же: на коротких кусках похожи любые две фразы.
  - Ничего не нашлось и после этого — соединять через пробел, как раньше.
  ⚠️ **Кусок без слов обязан отсекаться ДО поиска нахлёста.** Строка из одних пробелов непустая,
  но слов в ней ноль, и запасной поиск уходит в диапазон «с первого по нулевой» — в Swift это
  не ошибка, а trap, то есть падение приложения (на других платформах — исключение). Сейчас
  декодер отдаёт обрезанный текст и пустые куски пропускаются, так что случай недостижим, но
  защита стоит там, где ломается, а не там, где сегодня повезло.
  Проверяется самотестами на обоих примерах выше плюс на отрицательных («стол» + «стоп»
  не склеиваются).
- **Скачивание модели подчиняется §9.5** (прокси): в корпоративном контуре без
  прокси-авторизации оно упирается в `407`, и это самая частая причина «локальный движок не
  ставится». Там же требование не начинать загрузку молча.
- **Офлайн-fallback:** если выбрано облако, но сети нет, а локальная модель установлена —
  автоматически распознаём локально и **ненавязчиво уведомляем** пользователя.
- **Первая загрузка модели** после запуска занимает время (разовая инициализация под
  железо) — показываем индикатор «готовлю модель…», иначе похоже на зависание. Модель
  выгружается из ОЗУ после простоя.
- **Словарь-подсказка (§6) — только облако** (это фича Whisper `prompt`); **ИИ-исправление
  терминов (§6.1) работает с обоими движками** (нужны ключ и сеть).
- В историю пишется имя движка/модели в колонке `model`.
- **macOS (референс):** модель **Sber GigaAM v3** (`v3_e2e_ctc`, MIT, русский с пунктуацией),
  сконвертированная в **CoreML**, исполняется на **Neural Engine**. Конвейер на Swift без
  Python: мел-фронтенд → CoreML → CTC-декод. Раздаётся **скомпилированной** (`.mlmodelc`,
  ~400 МБ) как release-ассет отдельного тега репозитория.
- ⚠️ **Ограничение GigaAM: латинские слова выходят СМЕСЬЮ алфавитов, а не кириллицей.**
  Прежняя формулировка «пишет англицизмы кириллицей» неточна — на деле получается `Dпсиcк`,
  `Dpсиcк` вместо `DeepSeek`: латинская буква, потом кириллический слог, потом снова латинская.
  Причина в словаре sentencepiece (256 токенов): кириллица нарезана многобуквенными сабвордами,
  а **латиница представлена 52 одиночными буквами и ни одним многобуквенным куском**. Чтобы
  написать латинское слово, модель должна независимо угадать каждую букву подряд — при жадном
  argmax-декоде без языковой модели она срывается обратно на кириллические сабворды, они
  вероятнее.
  ⚠️ **Уточнение (проверено на живых диктовках 2026-08-19):** формулировка «правильными не будут
  никогда» была слишком сильной. Дело в ЧАСТОТНОСТИ, а не в принципиальной неспособности:
  частые слова модель собирает верно — `Amazon`, `Excel`, `MBA`, `PPC` в одной и той же записи
  вышли без ошибок, потому что встречались в обучении достаточно часто, чтобы цепочка одиночных
  букв выучилась целиком. А имя пореже в том же тексте поехало: `Clod AI` вместо `Claude AI`.
  Правило: **чем реже слово, тем вероятнее смесь алфавитов или кириллица**; редкие технические
  термины (ровно те, что кладут в словарь §6) страдают сильнее всего — их и чинят §6.2 и §6.1.
  **Полезное следствие:** слово со смешанными алфавитами — надёжный признак искорёженного
  иностранного термина (в нормальном русском тексте такого не бывает). Для детерминированного
  исправления это более крепкий сигнал, чем фонетическая близость, и работает как раз там, где
  проблема острее: словарь-подсказка §6 на локальном движке не действует вообще.
- **Windows (0.4.0):** реализовано на **ONNX Runtime** — та же модель **GigaAM v3 e2e CTC**,
  квантованная в **int8 (~215 МБ)**; мел-фронтенд портирован на C#, CTC-декод, чанки по 25 с,
  докачка модели своим release-ассетом с проверкой SHA-256, выгрузка из ОЗУ по простою,
  офлайн-fallback. Намеренное 🔀 отличие рантайма (ONNX vs CoreML) при едином поведении.
  Имя модели в истории — `gigaam-v3-e2e-ctc-int8` (macOS: `gigaam-v3-e2e-ctc`).

## 3. Запись аудио

- **Требование:** моно, **16 кГц**, компактно. Цель — быстрый аплоад в Whisper.
- macOS: `.m4a` (AAC, 16 кГц моно, 32 кбит/с) через `AVAudioRecorder`.
- Windows: допустимо **WAV 16 кГц моно** (PCM) через NAudio/WASAPI — Groq принимает WAV.
  (AAC/m4a — опционально позже, если важен размер.) Контейнер платформо-зависим, но
  параметры сигнала (моно/16 кГц) едины.
- **Мин. длительность 0.3 c** — более короткие записи считаем случайным нажатием: файл
  удаляем, ничего не отправляем.
- Временный файл записи удаляется после переноса в историю (или при ошибке/пустом ответе).
- ⚠️ **Отказ захвата обязан быть замечен и озвучен; записанное до отказа — распознаётся.**
  Найдено на Windows: у пользователя из 5 мин 48 с речи в текст попали 40 секунд. Микрофон
  перестал отдавать звук, а приложение этого не заметило — состояние осталось «идёт запись»,
  плашка рисовалась, в файл ничего не шло. Человек узнал об этом только в конце, когда
  переговаривать было уже нечего.
  Требования (все три ставятся дёшево и полезны независимо от причины отказа):
  - **причину от системы писать в лог** — часто это единственная улика (Windows: NAudio отдаёт
    её в `RecordingStopped`; macOS: `audioRecorderEncodeErrorDidOccur`, прерывания сессии);
  - **исключение в колбэке не должно убивать захват** — ошибка стоит одного буфера, не диктовки;
  - **сторож на молчание устройства**: если данные перестали поступать молча, первые два пункта
    не сработают. **3 секунды без прироста записи = мёртвое устройство.** Микрофон отдаёт данные
    и в полной тишине, поэтому пауза означает именно отказ, а не молчание говорящего.
    🔀 Механика платформенная: Windows смотрит на приход буферов, macOS — на `currentTime`
    у `AVAudioRecorder`, он растёт, пока идёт запись, и замирает, когда захват умер.
  В любом случае диктовка завершается немедленно, пользователю говорится, что микрофон замолчал,
  и **записанное распознаётся** — сказанное человеком не выбрасывается.
- ⚠️ **Пик уровня считать с расширением до 32 бит ДО снятия знака.** Модуль `Int16.min`
  в `Int16` не представим, а именно такой сэмпл приходит **при клиппинге** — на громком слове.
  На Windows это уронило поток захвата (см. выше, шесть минут потерянной речи), в Swift было бы
  ещё хуже: `abs(Int16.min)` там не исключение, а trap, то есть падение приложения.
  На macOS уровень берётся готовым API громкости (`averagePower(forChannel:)`, децибелы во
  `Float`) — арифметики по сэмплам нет вовсе, поэтому и ловушки нет (§4.2, волна идёт по
  реальной громкости с 0.9.17). Правило остаётся в силе для любого, кто соберётся считать пик
  сам: расширять до 32 бит ДО снятия знака.

## 4. Хоткей и режимы диктовки

- Два режима: **PTT (hold to talk)** — держишь клавишу, говоришь, отпускаешь; **Toggle** —
  нажал начать / нажал закончить. Оба режима — на всех платформах, выбор в Настройках.
- Клавиша-модификатор выбирается из списка (Настройки).
- **Дефолты (платформо-зависимы, намеренно):**
  - macOS: режим **PTT**, клавиша **Right Option** (keyCode 61).
  - Windows: режим **Toggle**, клавиша **Right Alt**.
- **Двойной тап для старта в режиме Toggle (macOS 0.9.10), опция, по умолчанию ВКЛ.**
  Лечит случайный старт: в `idle` запись начинается только двумя нажатиями клавиши подряд
  (порог **0.35 с**), одиночное нажатие не делает ничего. Стоп — всегда одиночное нажатие.
  Выключается в Настройках → Dictation («Двойной тап — старт»), тогда старт одиночным, как
  раньше. На PTT не влияет. Пункт меню «Диктовать» (§4.1) — всегда прямое действие, без
  двойного тапа. Компромисс, который надо озвучить в подсказке: двойной тап может конфликтовать
  с шорткатами других приложений.
- Требует системного доступа для глобального перехвата: macOS — Accessibility;
  Windows — низкоуровневый keyboard hook / `RegisterHotKey` (спец. разрешение не требуется).
- Состояние: `idle → recording → transcribing → idle`. Отражается индикатором (§4.2).

## 4.2. Индикатор диктовки (плашка / иконка трея)

Цель: в любой момент видно, что идёт диктовка, но **горит ровно один индикатор** — иначе
пользователь путается (у macOS есть ещё и своя оранжевая точка «микрофон занят», которую
приложение не контролирует).

- **Плашка (macOS 0.9.10, по умолчанию ВКЛ)** — плавающая капсула снизу по центру экрана,
  поверх окон, фокус не перехватывает. Живёт от старта записи до готового текста и проходит
  два состояния:
  ⚠️ **Волна обязана идти по РЕАЛЬНОЙ громкости входа, а не быть декоративной анимацией**
  (Windows с 0.6.0, macOS с 0.9.17). Польза не косметическая: живая волна показывает, что
  микрофон **действительно слышит**. С фиксированной анимацией занятый другим приложением
  микрофон, выбранный не тот вход или просто далёкий микрофон выглядят точно так же, как
  нормальная запись, — человек узнаёт о проблеме только по пустому тексту в конце.
  - **Уровень брать готовым API громкости, а не арифметикой по сэмплам** (macOS —
    `averagePower(forChannel:)`, децибелы во `Float`). Ручной подсчёт пика на `Int16` — тот
    самый источник бага из §3, который на Windows съел шесть минут речи, а в Swift дал бы
    падение приложения.
  - **Диапазон растянуть под речь:** тишина у микрофона ≈ −50 дБ и ниже, обычная речь живёт
    в −35…−10. По «сырой» шкале волна почти не двигается.
  - **Сглаживать несимметрично:** вверх быстро (слог должен быть виден сразу), вниз плавно.
    Сырой уровень скачет на каждом кадре, и без сглаживания выходит дёрганье, а не волна.
  - **В тишине волну НЕ гасить полностью** — оставлять заметный минимум амплитуды (≈¼).
    Мёртвая полоска читается как зависание приложения. Громкость управляет размахом волны,
    а не самим фактом её движения. 🔀 Форма волны платформенная (macOS — синусоида,
    масштабируемая уровнем; Windows — по реальному пику).
  Два состояния:
  - `recording` — анимированная волна + кнопка **«×»** (отменить: запись останавливается и
    выбрасывается, распознавания нет — новый путь, раньше отмены не было) и **«✓»** (стоп и
    распознать).
  - `transcribing` — волна и кнопки уходят, остаётся спиннер с подписью «Распознаю…».
  Пока плашка включена, **иконка трея не меняется вообще** (нейтральная в любом состоянии).
- **Фолбэк (плашка выключена в Настройках)** — старое поведение целиком на иконке:
  `recording` — акцентный цвет + пульсация, `transcribing` — статичный акцент другого цвета,
  `idle` — обычная. Пульсация только про запись.
- Переключатель — Настройки → Dictation («Показывать плашку записи внизу экрана»).
- Оформление плашки общее с индикатором загрузки модели (§2.5), чтобы это читалось как одна
  вещь: капсула-блюр, светлый спиннер и подпись.
- **Грабли платформы (macOS, зафиксировать):** цвет иконки статус-айтема задаётся **палитрой
  символа**, а не `contentTintColor` — последний не работает ни с template-, ни с не-template
  картинкой. Скругление HUD — только маской (`maskImage`), `layer.cornerRadius` не обрезает
  блюр с `blendingMode = .behindWindow`.
- **Windows (0.6.0):** окно плашки создаётся с `WS_EX_NOACTIVATE` — иначе оно забирает фокус и
  синтетический Ctrl+V (§5) уходит в саму плашку вместо поля пользователя. Позиция ставится
  через `SetWindowPos` в **физических пикселях**: приложение объявлено PerMonitorV2, и
  WPF-овские `Left`/`Top` промахиваются на мониторе с другим масштабом. Волна анимируется по
  реальному пику с микрофона (быстрая атака, медленный спад), спиннер — анимацией, а не тиками
  таймера. Метрики и порядок элементов совпадают с macOS: ×, волна, ✓; кнопки 28×28 r14, семь
  полос 3 px с шагом 5, капсула высотой 44 r22, шаг 10.
- **На каком экране показывать (мультимонитор).** Экран **активного окна** — того, куда поедет
  текст; если диктовку запустили из меню трея/меню-бара (§4.1) — экран **с курсором**. Монитор
  фиксируется на время сессии, чтобы капсула не прыгала при переключении окон. Окно результата
  (§5) открывается на том же экране, что и плашка.
  Поведение общее и подтверждено на обеих платформах: Windows 0.6.0 — `SetWindowPos` по
  монитору активного окна; macOS — `NSScreen.main` на момент создания панели даёт тот же
  результат. Проверено на двух дисплеях (встроенный + AirPlay в режиме «Расширить»), включая
  **разводящий случай**, когда курсор и активное окно на разных экранах: плашка садится к
  активному окну, а не под курсор.

### Список клавиш-модификаторов
macOS: Right/Left Option, Right/Left Command, Right Control, Function.
Windows-аналоги: Right/Left Alt, Right/Left Ctrl, Right/Left Win (маппинг по смыслу),
дефолт — Right Alt.

🔀 **Windows: предупреждение о конфликте с переключением раскладки (voica-win).** Системное
переключение раскладки по умолчанию висит на **левом** Alt+Shift; правый Alt его не трогает.
Одиночная клавиша-хоткей съедается хуком целиком (§4), поэтому при выборе **одиночного левого
Alt** раскладка перестаёт переключаться совсем. Двойной тап (§4) не спасает: первый тап тоже
съедается. Напоролись двое — живой пользователь и владелец проекта, повторивший сценарий.

- **Левый Alt из списка НЕ убирать.** У кого раскладка на Ctrl+Shift или Win+Space, конфликта
  нет; а сохранённые настройки хранят код клавиши, поэтому пункт просто исчез бы из меню,
  продолжая работать — страннее самой проблемы.
- Вместо этого при выборе одиночного левого Alt приложение обязано **проверить системное
  сочетание** (`HKCU\Keyboard Layout\Toggle`, значение `1` = Alt+Shift) и, если оно активно,
  показать под выбором предупреждение: раскладка перестанет переключаться, стоит взять правый
  Alt или сочетание.
- **На macOS аналога нет:** Option раскладку не переключает, предупреждать не о чем.

## 4.1. Меню трея / меню-бара (ручной запуск без хоткея)

- Клик по иконке открывает меню. Платформенная механика: macOS — меню открывает **любой**
  клик (левый и правый — стандарт NSStatusItem с меню); Windows — **правый** клик открывает
  контекстное меню (стандарт трея), левый клик может дублировать открытие меню.
- Пункты меню (в этом порядке):
  1. **«Диктовать»** — ручной старт/стоп диктовки без горячей клавиши. Семантика всегда
     toggle, независимо от выбранного режима хоткея: `idle` → старт, `recording` → стоп,
     `transcribing` → игнорировать.
  2. — разделитель —
  3. **«История…»**, **«Настройки…»** (macOS: шорткат ⌘,), **«О программе»**,
     **«Проверить обновления…»** (поведение и трансформация пункта — §10).
  4. — разделитель —
  5. **«Завершить»** (macOS: ⌘Q).

## 5. Вывод результата (Output)

- Два режима, выбор в Настройках:
  - **`insert` (по умолчанию)** — положить текст в буфер обмена **и** синтезировать вставку
    в активное поле (macOS — ⌘V, Windows — Ctrl+V через `SendInput`).
  - **`window`** — показать редактируемое окно результата (как исторически).
- **Текст ВСЕГДА копируется в буфер** — фолбэк, даже в режиме `insert`.
- 🔀 **Windows: порядок синтетической вставки (voica-win, стоило ошибочного фикса).** Симптом у
  живого пользователя: вместо продиктованного текста в поле попадала одна буква `v` (в русской
  раскладке «м»), причём плавающе. Причина: клавиша-хоткей съедена хуком целиком (§4), система
  продолжает считать Alt зажатым, и синтетический Ctrl+V приходит как **Alt+Ctrl+V** — а это
  уже не «вставить».
  Правило: перед вставкой **отпускать модификаторы, которые система всё ещё считает нажатыми,
  но ТОЛЬКО ВНУТРИ аккорда** — сначала Ctrl вниз, затем отпускания, затем `V`.
  ⚠️ Отпускать Alt **отдельным событием нельзя**: окно читает это как одиночный тап по Alt,
  открывает своё меню и глотает вставку — то есть «фикс» воспроизводит ровно тот баг, который
  лечит. Измерено на стенде: контроль вставляет, старый порядок не вставляет, отдельное
  отпускание не вставляет, отпускание внутри аккорда вставляет.
  Ctrl в список отпускаемых **не входит** — он и должен быть нажат.
- **Экран окна результата (мультимонитор):** тот же, где показывалась плашка (§4.2), то есть
  экран активного окна. Окно результата не должно открываться на основном мониторе, если
  диктовали на втором. Проверено на macOS на двух дисплеях.

## 6. Словарь терминов (Vocabulary)

- Freeform-строка в Настройках (многострочное поле). Слова/названия/жаргон, которые Whisper
  часто коверкает.
- Готовится в поле `prompt`: **тримминг**; если пусто → `prompt` не отправляем; если длиннее
  **бюджета 800 символов** → берём **хвост** (Whisper учитывает только последние ~224 токена).
- **Почему бюджет вообще есть.** Ограничение не наше и не провайдера, а самой модели: у Whisper
  текстовый контекст декодера 448 токенов, под `prompt` отводится половина — ~224 токена. Всё,
  что не влезло, модель отбрасывает. Режем сами и **сохраняем хвост**, чтобы обрезка была
  предсказуемой, а не случайной. Практическое следствие для пользователя: **важные термины
  держать в конце списка** — при переполнении выживает именно конец.
- **Оценка 800 символов приблизительная**: 224 токена — это ~900 символов латиницей, но
  кириллица токенизируется хуже (примерно вдвое), так что русскоязычный словарь упирается в
  лимит раньше бюджета. Считать это верхней границей, а не гарантией.
- Это **подсказка, не жёсткая замена**: слова-омофоны обычных (напр. `voica`↔«voice») может не
  перебить — это ожидаемо (для железной замены — §6.1, ИИ-исправление).
- **С локальным движком словарь-подсказка не работает вообще** (§2.5: у GigaAM нет входа для
  `prompt`). Раньше там ИИ-исправление §6.1 было **единственным** механизмом приведения терминов;
  с 0.9.15 первым идёт детерминированное исправление (§6.2), которому не нужны ни ключ, ни сеть.

## 6.2. Детерминированное исправление терминов (правила, macOS 0.9.15)

Правила, а не модель: ноль скачивания, ноль ОЗУ, работает офлайн и **одинаково на обоих
движках**. Живёт в общем хвосте распознавания, **ДО** ИИ-правки §6.1 — модель получает уже
прибранный текст, и ей остаётся только то, что требует понимания смысла.

- **Работает, если словарь непустой; галочка «Исправлять термины правилами» на вкладке
  Vocabulary, по умолчанию ВКЛючена** (macOS 0.9.17).
  ⚠️ **До 0.9.17 настройки не было намеренно**, и обоснование звучало так: человек завёл словарь
  ровно затем, чтобы эти слова писались правильно, спрашивать второй раз незачем. Довод оказался
  неполным: правило ПОДМЕНЯЕТ слова, и если оно ошибётся на чьих-то терминах, единственным
  способом его унять было бы стереть словарь и ждать обновления. Выключатель — не про вкус,
  а про возможность остановить правило, меняющее текст. См. §6.5.
- **Зачем вообще, если есть §6.1.** У LLM нет порога ни в одну сторону, это измерено на живых
  диктовках: один и тот же искажённый термин она то чинила (`Dпсик`, `Deepsic`), то не замечала
  (`Deepsc`), а однажды подменила словарным термином слово, которого в словаре не было
  («Fix terms» → `focus-radio`). У правила порог фиксирован и одинаков всегда.
- **Составные термины ищутся окном до двух слов подряд.** Ширина окна НЕ выводится из числа
  слов в термине: движок перекашивает в обе стороны — «Claude Code» приезжает одним словом
  (`клодкод`), а «Tailscale» двумя (`Tail scale`). Два условия обязательны:
  - **склейка сопоставляется только точно.** Само склеивание уже допущение; второе допущение
    поверх него съедает соседей — «в Cowork» склеивалось в `вCowork`, расходилось с `Cowork`
    на одну букву и глотало предлог;
  - **каждое слово в окне обязано дать хотя бы одну согласную**, иначе окно проглатывает
    пустышку: «дипсик и» даёт тот же костяк `dpsk`, и союз исчезал из текста.
- **Кандидаты трёх сортов, требования к ним РАЗНЫЕ:**
  - **смешанный алфавит** в одном слове (`Dпсик`, `Dpсиcк`, `раadio`) — сам по себе
    доказательство порчи, в нормальном русском тексте такого не бывает (причина — §2.5).
    Достаточно совпадения согласного костяка; побуквенно такое слово от термина далеко.
  - **чистая латиница** (`Deepsc`) — сама по себе ничего не доказывает, в русской диктовке
    полно нормальных английских слов. Поэтому вдобавок к костяку требуется побуквенная
    близость **≥ 0.5** (Левенштейн, приведённый к доле). Проверено: `Deepsc`/`DeepSeek` = 0.62
    и `Depsic`/`DeepSeek` = 0.50 → чиним.
    ⚠️ **Порог был 0.6 и снижен в macOS 0.9.18 по измерению, а не по случаю.** Живой промах —
    `Depsic` с точным костяком и близостью ровно 0.50. Прогон по всей истории (138 строк,
    тексты + сырые) при 0.5 не изменил НИ ОДНОЙ строки против 0.6: двадцать замен там и там.
    ⚠️ **«Greek» → «Groq» держит не порог, а костяк** (`grk` против `grq`: `c` сворачивается
    в `k`, а `q` — нет). Прежняя редакция §6.2 называла причиной порог — это было неверно,
    и на порог 0.5 ловушка не реагирует. `Greek`/`Groq` = 0.40 и без того мимо.
  - **чистая кириллица** (`клодкод`) — не доказывает ничего вовсе, поэтому только точный
    костяк и **термин обязан быть латинским** (см. про грамматику ниже).
- **Минимальная длина костяка ступенчатая — по силе доказательства:** смешанный алфавит **2**,
  латиница **3**, кириллица **4**. Не подгонка под случай, а следствие того, что короткий
  костяк не значит ничего: `vice` даёт `vk` ровно как `Voica`, а побуквенная близость выходит
  0.60 — впритык проходила порог, и «vice versa» превращалось в «Voica versa». Ловить это
  подкручиванием порога до 0.62 было бы подгонкой под один случай.
- **Русские термины правила НЕ трогают вовсе.** Скелет `аферту` точно совпадает с `оферта`,
  но подстановка дала бы «Отправь оферта»: сказанное стоит в падеже, а словарь хранит
  именительный. Склонение требует понимания смысла — это работа §6.1. Латинские термины
  в русском тексте не склоняются, с ними безопасно.
- **Согласный костяк** — слово транслитерируется в латиницу, выкидываются гласные, `c`
  сводится к `k`, повторы схлопываются. Гласные выкидываем потому, что именно их модель теряет
  и путает, а согласные держатся. Все живые искажения `DeepSeek` — `Dпсик`, `Dпсиcк`, `Deepsc`,
  `Dpсиcк` — дают тот же костяк `dpsk`, что и сам термин.
- **Ничего не подошло — не трогаем.** Ложное срабатывание дороже пропуска: пропуск подберёт
  LLM следом, а испорченное слово никто не заметит. Тесты обязаны покрывать обе стороны, и
  отрицательные важнее.
- **Как проверять правила (методика, обязательна к повторению при любой правке порогов).**
  Пороги ставятся по данным, а не по интуиции — на глазок они промахиваются:
  1. **Корпус собирается сам.** `raw_text` (§7) пишется при каждой диктовке, где обработка
     что-то изменила, — каждая строка это готовая пара «как услышалось → как должно быть».
  2. **Ловушки важнее находок.** Надиктовать обычную русскую речь, созвучную терминам, и
     проверить, что правила молчат. Живые: «Вика» даёт костяк `Voica` один в один, «Папа» —
     `API`, «усы» — `ЕИС`, «депеша» — `DeepSeek` (0.75), «Колодка» — `Claude Code` (0.80).
  3. **Прогон по ВСЕЙ истории — обязателен.** Придуманные ловушки пропускают то, что находит
     живой текст: `vice versa` поймалось только так. Инструмент — `--normalize-corpus <файл>`,
     печатает только изменившиеся строки. Каждое изменение обязано быть оправдано.
  4. **Всё, что нашлось, морозится фикстурами самотеста** — и положительное, и отрицательное.
  Результат на 2026-08-19: 60 диктовок, 20 уникальных замен, все верные, ложных ноль.
- **Замена — на каноническое написание из словаря** (регистр берётся оттуда же, §6). Пунктуация
  и пробелы вокруг слова сохраняются.
- **Известное ограничение первой версии:** составные термины сопоставляются целым словом,
  поэтому `раadio` из `focus-radio` не чинится — это пропуск, не порча. Фонетический матчинг
  для облачных искажений (`дипсик` чистой кириллицей) тоже отложен: у облака есть
  словарь-подсказка `prompt`, вмешивающаяся ещё на распознавании, так что дыра там меньше.
- **Асимметрия польза/движок — осознанная.** Смешанный алфавит это болезнь GigaAM; Whisper
  пишет латиницу нормально. По существу §6.2 — починка локального режима, на облаке тихая
  страховка.
- **Пользовательская документация:** `docs/terms-ai.ru.md` — гайд «Словарь терминов и
  ИИ-исправление» человеческим языком (зачем, как включить, разница движков, приватность,
  что делать если не сработало). Ссылка из README. Windows-порт должен зеркалить и текст:
  поведение общее, а вопросы у пользователей одинаковые.

## 6.4. Непарные кавычки (проверка на выдаче, macOS 0.9.17)

Последняя проверка перед вставкой текста — в единственной точке выдачи, ПОСЛЕ обоих
механизмов (§6.2 и §6.1). Наследить может каждый из них, и определить виноватого нельзя:

- **Движок.** CTC-декод жадный, идёт по кадрам и не имеет состояния «кавычка уже открыта»
  (§2.5). Незакрытая ёлочка для такой схемы не сбой, а нормальный исход.
- **Модель.** Подставляя латинский термин в русский текст, любит обернуть его в кавычки
  вопреки прямому запрету в промпте — и делает это несимметрично. Наблюдалось живьём:
  «с термином «DeepSeek в словаре».

**Галочка «Чинить кавычки» в разделе «Очистка текста» на вкладке Dictation, по умолчанию
ВКЛючена** (§6.5).

Правило работает в три шага.

**1. Прямые кавычки → ёлочки, по положению.** Движок пишет как придётся: в его словаре есть
и `«`, и `»`, и `"`, каждая предсказывается отдельно, и в одной фразе встречаются все три вида.
Сторону определяем по соседям, как это делают текстовые редакторы: после пробела, двоеточия или
скобки и перед буквой — открывающая, иначе закрывающая.
⚠️ **Только если в тексте есть кириллица.** Ёлочки — русская типографика; в английской диктовке
(§2 — авто-детект языка) прямые кавычки правильны, и трогать их нельзя.

**2. Пробел после двоеточия**, если движок его забыл перед открывающей кавычкой: `в ответ:"Давай`.

**3. Балансировка — и вот тут выбор неочевиден.** На каждую лишнюю закрывающую надо что-то
выбросить, но что именно, зависит от смысла:
- если какая-то из УЖЕ СПАРЕННЫХ закрывающих выглядит **преждевременной** — за ней запятая
  и продолжение со строчной, — выбрасываем её. Значит цитата длиннее, а «лишняя» закрывает её
  по-настоящему. Живой случай: `«Да", это стопроцентный вариант"` — человек закавычил всю фразу,
  движок закрыл после первого слова. Правильный ответ `«Да, это стопроцентный вариант»`,
  а НЕ `«Да», это стопроцентный вариант`;
- если преждевременных нет, лишняя и есть ошибка — выбрасываем её саму. Иначе фраза
  `Он сказал «да». Потом ушёл»` потеряла бы верную закрывающую после «да».

Различает эти два случая только то, что стоит ПОСЛЕ кавычки: точка и заглавная — настоящий
конец цитаты, запятая и строчная — цитата продолжается. По форме они одинаковы (одна
открывающая, две закрывающих), а выбрасывать надо разные.

Непарные открывающие удаляются. Вложенность игнорируется — в диктовке её не бывает.

**Именно удалить, а не дописать недостающую.** На практике это почти всегда незакрытая
открывающая в прямой речи («…сказал: «На, занимайся»), и где именно кончается цитата, знает
только говоривший. Дописывать закрывающую значило бы угадывать границу — а лишний знак читается
как опечатка и без него фраза выглядит нормально. Проверено на истории: четыре строки с
ёлочками, все четыре — незакрытые открывающие.

⚠️ Проверка обязана стоять **после** ИИ-правки: до неё она проверяла бы работу модели раньше,
чем модель её выполнила. Это тот же принцип, что у порога правдоподобия из §6.1.

## 6.5. Выключатели правил, меняющих текст (macOS 0.9.17)

Правил, которые меняют написанное, три: термины подменяются (§6.2), филлеры удаляются (§6.3),
кавычки правятся (§6.4). **У каждого обязан быть свой выключатель, все включены по умолчанию.**

- **Почему у каждого, а не один общий.** Правила независимы и ошибаются по-разному; общий
  выключатель заставлял бы отказаться от трёх ради одного.
- **Почему вообще.** Не про вкус, а про возможность остановить правило, которое ошиблось на
  конкретных словах пользователя, не дожидаясь обновления. До 0.9.17 галочка была только у
  филлеров, и унять ошибающиеся термины можно было лишь стерев словарь.
- **Где стоят.** Кавычки и филлеры — раздел **«Очистка текста»** на вкладке Dictation; термины —
  на вкладке Vocabulary, **над** тумблером ИИ. Порядок не случаен: сначала то, что работает
  всегда и бесплатно, потом необязательная надстройка.
- **Прогон по корпусу (`--normalize-corpus`) обязан уважать выключатели** — иначе замер
  показывает не то, что видит пользователь.
- Ключи настроек: `stripFillers`, `fixQuotes`, `fixTermsByRules`; все три сбрасываются вместе
  с остальными настройками (§11).

## 6.3. Удаление слов-паразитов (правила, macOS 0.9.17)

Тянущиеся звуки — «э-э-э», «ммм», «хмм» — в речи не значат ничего, а в тексте мешают.
Убираются правилами, до ИИ-правки, на обоих движках. Локальный движок пишет их честно,
облачный Whisper чаще сглаживает сам, поэтому польза здесь тоже асимметрична (см. §6.2).

- **Галочка в Настройках → Dictation, раздел «Очистка текста», по умолчанию ВКЛючена.**
  Здесь довод сильнее, чем у прочих правил: это **удаление сказанного**, и тому, кто
  расшифровывает речь дословно, оно навредит. См. §6.5.
- **Правило смотрит на ФОРМУ слова, а не на список написаний.** Кандидат — токен, который
  после схлопывания дефисов и повторов ужимается до одной-двух букв: `эээ`→`э`, `Э-э-э`→`э`,
  `хмм`→`хм`. Перечислять написания бессмысленно: одно и то же мычание распознавание пишет
  каждый раз иначе (в живой истории нашлось 12 разных форм на 14 случаев).
- **Одиночные звуки удаляются, только если их ТЯНУЛИ.** «а» — союз, «у» и «о» — предлоги,
  «и» — союз; сами по себе они неприкосновенны. Растяжка (`А-а`, `ээ`) снимает неоднозначность.
  Формы, которые целиком мусор (`хм`, `э`), удаляются и без растяжки.
  ⚠️ **Список безусловных филлеров обязан состоять из форм до двух букв** — ровно их пропускает
  гейт длины. Всё длиннее не сработает никогда и будет лежать в списке мёртвым: так там и лежали
  `мхм`, `угу`, `ага` (нашлось сверкой с Windows, macOS 0.9.18).
- **«Угу», «ага», «мхм» НЕ удаляются, и это решение, а не гейт.** Это согласие — в них есть
  смысл, в отличие от мычания; диктовка из одного «Ага.» после удаления стала бы пустой.
  Тот же довод, по которому растянутое «ну-у-у» распрямляется, а не выбрасывается.
  `эм` не филлер по другой причине: так движок пишет «GigaAM» — «Джига Эм».
- ⚠️ **Растянутое НАСТОЯЩЕЕ слово распрямляется, а не удаляется:** `Ну-у-у` → `Ну`, `ноо` → `но`.
  Удалить его — потерять смысл. Список распрямляемых слов ЯВНЫЙ: распрямлять всё подряд нельзя,
  иначе `PPC` станет `Pc`, а `All` — `Al`.
- ⚠️ **Не трогать: токены с цифрами и аббревиатуры из заглавных.** Обе оговорки написаны кровью
  на прогоне по истории: схлопывание повторов превращало `100` в `10`, а `ИИ` сворачивалось
  в `и` и удалялось как филлер. Отдельно: `мм` после числа — это миллиметры, не мычание.
- **Филлер в начале предложения — следующее слово в заглавную.** Иначе «Э-э-э, проверка»
  давало «проверка» со строчной, и фраза выглядела неряшливо. Признаков начала предложения
  **два**, и второй обязателен: заглавная у самого филлера **либо** уцелевший разделитель,
  закрывающий предложение (`.`, `!`, `?`, `…`). Одного регистра мало — прогон по истории дал
  три живых случая подряд со СТРОЧНЫМ филлером после точки: «…возьмут на улицу. э-э, на работу».
  Строчный филлер в середине фразы регистр не меняет.
  ⚠️ **Решение принимается ПОСЛЕ выбора разделителя** (их вокруг филлера два, уцелевает один),
  иначе признак проверяется по знаку, который в текст не попадёт.
- **Уборка следов запускается, ТОЛЬКО если что-то удалили,** и чинит исключительно свои следы
  (сдвоенный пробел, знак в начале строки). Пунктуацию остального текста не трогает: иначе
  включённая галочка переформатировала бы чужие многоточия, чего никто не просил. Повисших
  запятых не остаётся само собой — при разборе пропускается разделитель после филлера.
- **Проверять по методике §6.2** (корпус, ловушки, прогон по всей истории). Здесь она окупилась
  особенно наглядно: десять юнит-тестов были зелёными, а прогон по живым диктовкам поймал ПЯТЬ
  дефектов подряд — исчезающее `ИИ`, битые числа, `PPC`→`Pc`, потерянную точку в конце фразы
  и переформатирование чужой пунктуации.

## 6.1. ИИ-исправление терминов (LLM-постобработка, opt-in)

- Тумблер в Настройках (раздел словаря), **по умолчанию выкл**. Работает только при непустом
  словаре. Применяется к результату **обоих** движков (облако и локальный, §2.5).
- После распознавания текст отправляется в Groq chat-модель:
  `POST https://api.groq.com/openai/v1/chat/completions`, `temperature: 0`,
  `max_completion_tokens: 4096`, таймаут **20 с**. Модель — **не захардкожена**, см. ниже.
- **Динамический выбор модели (само-исцеление).** Groq периодически удаляет/переименовывает
  модели (в 0.9.3 исчез прежний `qwen/qwen3-32b` → 404). Чтобы это НЕ требовало срочного
  релиза:
  - **Живой список:** `GET /v1/models` ключом пользователя → фильтр chat-моделей. Фильтр —
    **denylist** (у Groq нет флага «это chat»): исключаем id, содержащие
    `whisper/tts/orpheus/guard/embed/moderation/distil`; остальное считаем пригодным (новые
    chat-семейства подхватываются сами).
  - **Настройка `chatModel`:** `"auto"` (по умолчанию) или конкретный id. В `"auto"` приложение
    берёт лучшую доступную по **приоритет-цепочке** (`openai/gpt-oss-120b` → `qwen/qwen3.6-27b`
    → `openai/gpt-oss-20b` → `llama-3.1-8b-instant`); если ни одной нет — первую из живого списка.
    Резолв кэшируется (`resolvedChatModel`, сид `openai/gpt-oss-120b` для первого запуска/офлайна).
    Отправляем всегда `activeChatModel` (ручной выбор или кэш).
    **Цепочка — расходник, а не константа:** её пересматривают, когда провайдер снимает модели.
    История: `gemma2-9b-it` пропала из живого списка; `llama-3.3-70b-versatile` снята Groq
    16.08.2026 (замену провайдер назвал сам — gpt-oss-120b и qwen3.6-27b). Порядок внутри
    цепочки — по убыванию размера среди того, что реально раздаётся.
    **Порядок вымерен, а не угадан (2026-08-20).** Раньше цепочка сортировалась по размеру
    модели — это прокси, а не измерение, и чужие бенчмарки тут не помогают: они меряют общий
    интеллект, а не правку терминов в русском тексте. Замер на живых искажениях из истории
    (`scripts/eval-chat-models.py`, 15 случаев, из них 6 — ловушки из обычной русской речи):
    `openai/gpt-oss-120b` и `qwen/qwen3.6-27b` дали **одинаковые 12 из 15**. Утверждение, что
    qwen «значительно лучше» на смешанном русско-английском, НЕ подтвердилось.
    Первым остаётся gpt-oss-120b: при равной точности он втрое быстрее и вчетверо дешевле (для
    правки с бюджетом в секунду-две это решает), и у него нет режима «вернуть пустоту» — qwen
    на одном случае истратила бюджет токенов на рассуждения и вернула пустой ответ (поймано
    порогом правдоподобия, fail-open).
    ⚠️ **Обе модели испортили одну и ту же обычную фразу**, по-разному: «Вика прислала кода на
    200 строк» → gpt-oss сделала «Вика прислала **Code**», qwen — «**Voica** прислала кода».
    Детерминированные правила §6.2 её не трогают. Это и есть довод, почему правила идут первыми:
    они не угадывают там, где нет доказательств порчи.
    ⚠️ **При `temperature: 0` ответы всё равно НЕ строго детерминированы**: один и тот же случай
    («эй-ай» → `AI`) в разных прогонах то чинится, то нет. Одиночное наблюдение ничего не
    доказывает — менять цепочку только по результату замера.
    **Лимиты free tier (измерено):** одна диктовка — **~750 токенов** (356 промпт + ~400 ответ;
    ответ большой, потому что модель тратит токены на рассуждения). При нижних лимитах это
    **~10 диктовок в минуту и ~265 в сутки**. Для живой работы с запасом, но «сколько угодно»
    это не значит: перемерять, если промпт или словарь заметно вырастут.
  - **Само-исцеление:** verify (ниже) и 404 во время диктовки пересчитывают резолв; если ручной
    выбор пропал из живого списка — молча возвращаемся к `"auto"`. Диктовка при 404 уже безопасна
    (fail-open) → провайдер убил модель, приложение чинит себя, релиз не нужен.
  - **Миграция:** сохранённая снятая с раздачи модель → сброс на `"auto"`, а закэшированный
    `resolvedChatModel` — на сид. Список снятых ведётся в коде и пополняется при выводе моделей;
    сейчас в нём `qwen/qwen3-32b` и `llama-3.3-70b-versatile`. Нужен именно список, а не только
    само-исцеление по 404: иначе пользователь с ручным выбором мёртвой модели каждый раз платит
    одним неудачным запросом.
  - **403 vs 404:** `/models` показывает наличие, но не org-доступ. Пробный запрос к резолвнутой
    модели различает **403** (заблокирована в Groq-org — «разрешите в console.groq.com → Settings →
    Limits»; включить нужно ОДНУ выбранную) и **200** (доступна).
  - **403 во время диктовки → уведомление (macOS 0.9.13).** Само-исцеление тут бессильно: модель
    жива, не хватает доступа. Поэтому вместо молчания — системное уведомление с id модели и
    подсказкой про console.groq.com, **не чаще раза на модель за сессию**. Без него постобработка
    отваливалась бы тихо на каждой диктовке, и человек считал бы, что функция не работает вовсе.
  - **Фильтр `compound`.** `groq/compound` и `compound-mini` — не chat-модели, а агентные системы
    Groq с собственным роутингом и инструментами: лишний слой для одной короткой правки терминов,
    к тому же роутят на модели, которых у организации может не быть. Отсекаются denylist'ом
    наравне с `guard`/`moderation`.
  - **Фильтр `allam`.** `allam-2-7b` — арабоязычная модель. Отсекается не за качество, а из-за
    запасного выбора: живой список сортируется по алфавиту, а `pickRecommended` в крайнем случае
    берёт первый элемент — «allam» оказывается первым в алфавите и молча становится запасной
    моделью для исправления РУССКИХ терминов. Аудитория обеих платформ сейчас русскоязычная.
    Если появится запрос на арабский — вернуть модель и выбирать запасную по языку, а не по
    алфавиту. ⚠️ Фильтр работает по подстроке, поэтому нужна проверка, что `allam` не цепляет
    `meta-llama/...` (там `a-llama`, не `allam`) — закрыто самотестом.
  - **Самотесты, читающие настройки, обязаны сбрасывать кэш резолва.** Проверка «в `auto`
    активная модель равна сиду» зависела от реального состояния машины: после ручного выбора
    модели в настройках в `resolvedChatModel` лежит она, и тест падал на ровном месте. На CI
    настройки чистые, поэтому дефект не ловился. Правило: снимать снимок `chatModel` И
    `resolvedChatModel`, удалять ключи, проверять, восстанавливать.
- Промпт (смысловой контракт, дословно см. референс `GroqClient.postProcessPrompt`):
  исправить только искажённые варианты словарных терминов, согласуя с падежом/контекстом;
  слово, совпадающее со словарным термином в другом регистре, — правильное, регистр не менять;
  при неоднозначности выбирать термин по **фонетической близости**; больше ничего не менять.
  - **Вычистка рассуждений reasoning-моделей (macOS 0.9.14).** Часть современных chat-моделей
    возвращает ход мысли прямо в `content`, обёрнутым в `<think>…</think>`, а собственно ответ —
    после него. Без вычистки эти рассуждения целиком уезжают в текст пользователя вместо
    диктовки. Это не гипотеза: `qwen/qwen3.6-27b` — **второе звено нашей же цепочки**, то есть
    любой, у кого заблокирована `openai/gpt-oss-120b`, ловил это на каждой диктовке.
    Правило: перед выдачей вырезать все блоки `<think>…</think>` (регистронезависимо, теги
    могут нести атрибуты, блоков может быть несколько); **незакрытый** тег означает, что ответ
    обрезали по `max_completion_tokens` посреди рассуждения — полезного текста дальше нет,
    режем до конца. Полагаться на параметры провайдера (`reasoning_format` и подобные) НЕ
    следует: они специфичны для конкретного API и на модели без рассуждений могут дать 400,
    а это по fail-open означает молчаливую потерю исправления для ВСЕХ моделей. Чистка на
    своей стороне работает независимо от провайдера.
  - **Порог правдоподобия ответа.** Исправление терминов подменяет отдельные слова, поэтому
    длина ответа не может радикально отличаться от исходной. Если после вычистки не осталось
    ничего либо ответ длиннее исходного больше чем вдвое (`text.count * 2 + 50`) — считаем,
    что модель наговорила лишнего, и отдаём исходный текст. Это вторая линия к fail-open:
    ловит болтливость любых будущих моделей, а не только формат `<think>`.
- **Fail-open:** любая ошибка/не-2xx/таймаут/пустой ответ → доставляется исходный текст Whisper.
  Постобработка никогда не блокирует диктовку.
- Пока идёт постобработка, состояние остаётся `transcribing` (иконка показывает работу).
- В историю пишется **финальный** (исправленный) текст.
- Документировать для пользователя: словарь задаёт каноническое написание (регистр!), и если
  Groq-org пользователя ограничивает модели — chat-модель нужно разрешить в консоли Groq.
- **Verify + выбор модели (UX):** при включении тумблера (и при открытии настроек с уже
  включённым) — тянем живой список, резолвим/само-исцеляем, пробным запросом проверяем
  резолвнутую. Нативный статус рядом: зелёный «модель доступна: `<id>`»; при само-переключении
  «выбранная модель недоступна — переключились на `<id>`»; при **403** — «разрешите в
  console.groq.com → Settings → Limits»; если у ключа нет подходящих chat-моделей —
  соответствующий текст; прочие ошибки — их текст. Рядом — **поповер выбора**: «Рекомендуемая
  (автоматически)» + живой список для power-user. Виден только при включённом тумблере. Не
  блокирует UI.

## 7. История (SQLite)

- Таблица `transcriptions`:
  `id INTEGER PK AUTOINCREMENT, created_at INTEGER (unix-секунды), text TEXT NOT NULL,
  language TEXT, duration_sec REAL, audio_filename TEXT, model TEXT, raw_text TEXT`.
- **`raw_text` — текст движка ДО ИИ-исправления терминов (macOS 0.9.15).** Заполняется, **только
  когда правка реально что-то изменила**; совпало — `NULL`, две одинаковые копии не нужны.
  Зачем: без сырого текста невозможно понять, кто наследил в результате — движок или модель.
  За один день это заблокировало четыре разбора подряд (кто подчистил филлеры, кто поставил
  непарную кавычку, почему словарный термин подменил слово, которого в словаре нет) и сделало
  невозможной оценку детерминированной нормализации. Побочный эффект намеренный: **каждая строка
  с непустым `raw_text` — готовая пара «сырое → исправленное»**, то есть корпус для замеров
  копится сам собой при обычной работе.
  Приватности это не меняет: финальный текст и так хранится, новых сущностей не появляется —
  и `raw_text` подчиняется тем же retention и «удалить все данные».
  ⚠️ **Миграция обязательна:** базы, созданные раньше, колонки не имеют, а `CREATE TABLE IF NOT
  EXISTS` их не трогает. Выполнять `ALTER TABLE transcriptions ADD COLUMN raw_text TEXT`,
  игнорируя ошибку «колонка уже существует» — это штатный исход на свежей базе.
- Хранилище **вне бандла/exe**, чтобы переживать обновления:
  - macOS: `~/Library/Application Support/com.ushakov.voica/` (`history.sqlite`, `audio/*.m4a`)
  - Windows: `%APPDATA%\Voica\` (`history.sqlite`, `audio\*.wav`)
- Функции: список (новые сверху), повторное копирование, воспроизведение аудио, удаление записи,
  **экспорт всей истории** (см. ниже).
- **Поиск по истории (macOS 0.9.15).** Поле поиска над списком; фильтрует по подстроке без
  учёта регистра. Записи копятся тысячами, и скролл перестаёт быть способом навигации.
  - **Ищем и по `text`, и по `raw_text`**: человек помнит, что он СКАЗАЛ, а не то, во что это
    превратили правила §6.2 и модель §6.1. Искать только по финальному тексту — значит не найти
    свою же диктовку по запомнившемуся слову.
  - Фильтрация по паузе набора, а не по каждой букве.
  - **Экспорт фильтру НЕ подчиняется** — остаётся действием по всей истории (см. ниже). Кнопка
    стоит под списком, но это намеренно разные вещи: отфильтровать для просмотра и выгрузить
    архив — разные задачи, а «экспорт» без оговорок читается как «всё».
  - Пустой результат показывает «ничего не найдено», а не «история пуста»: это разные состояния.
- **Мультивыделение и удаление пачкой (macOS 0.9.10):** в списке выделяется несколько записей
  штатными жестами платформы (macOS — Cmd/Shift/Cmd+A). Удаление работает по всему выделению,
  подтверждение показывает количество. Клавиша Delete и контекстное меню по правому клику
  делают то же. При выборе больше одной записи панель деталей показывает счётчик, а
  «Копировать» и «Воспроизвести» гаснут — они осмысленны только для одной записи.
  Реализация обязана удалять пачку **одним проходом** (одна транзакция, одно чтение таблицы
  на всю пачку), а не циклом по однозаписному удалению.
- **Экспорт истории (macOS 0.9.9):** кнопка «Экспорт…» в окне History (действие по ВСЕЙ истории,
  отдельно от per-record кнопок; неактивна при пустой истории). Диалог сохранения с выбором
  формата — **Markdown / CSV / JSON** (дефолт `.md`; смена формата в попапе меняет расширение
  имени). Экспортируется **только текст + метаданные** (аудио НЕ входит), все записи в порядке
  как в списке (новые сверху). Поля:
  - **Markdown:** `# Voica — history (N)`, затем на запись `## <yyyy-MM-dd HH:mm>`, строка
    метаданных `_язык · длит.с · модель_` (пропуская пустые), затем текст.
  - **CSV:** заголовок `created_at,text,language,duration_sec,model`; **BOM `U+FEFF`** в начале
    (кириллица в Excel); RFC-4180-экранирование (поле с `"`/`,`/переводом строки — в кавычках,
    внутренние `"` удваиваются). Дата `yyyy-MM-dd HH:mm`, длительность с 2 знаками.
  - **JSON:** массив объектов `{id, created_at (ISO-8601), text, raw_text?, language?,
    duration_sec?, model?, audio_filename?}`; nil-поля опускаются; pretty-print, ключи
    сортированы. `raw_text` попадает только в JSON: это машинный формат, из которого достают
    корпус. Заголовок **CSV намеренно НЕ меняем** — он документированный контракт, а лишняя
    колонка там ломала бы чужие разборщики ради данных, нужных одному сценарию.
  - Дата в MD/CSV — стабильный `yyyy-MM-dd HH:mm` (локаль `en_US_POSIX`, не зависит от системной).
- **В деталях/списке истории показывается использованный движок/модель** (поле `model`) —
  в строке метаданных рядом с датой/языком/длительностью. Значения: облако — реально
  выбранная STT-модель (`whisper-large-v3-turbo` или `whisper-large-v3`, см. §2); локальный
  движок — `gigaam-v3-e2e-ctc` (macOS) / `gigaam-v3-e2e-ctc-int8` (Windows).
- **Потокобезопасность:** весь доступ к БД сериализован (serial queue на macOS / эквивалентный
  замок или выделенный поток на Windows). Все методы БД идут через него.

## 8. Хранение аудио и retention

- Тумблер «Хранить аудиозаписи» (по умолчанию вкл). Если выкл — аудио не сохраняется, остаётся
  только текст.
- «Удалять аудио старше N дней», по умолчанию **30**, `0` = хранить всегда.
- Чистка при запуске: удаляет аудиофайлы старше N дней и **обнуляет `audio_filename`**; текст
  записи остаётся.

## 9. Хранение ключа Groq

- В **защищённом локальном файле**, не в коде и не в репозитории:
  - macOS: файл `credentials`, права `0600`.
  - Windows: файл, защищённый **DPAPI** (или Windows Credential Manager).
- Fallback для разработки: переменная окружения `GROQ_API_KEY` (если файла нет).
- Сохранение ключа — кнопкой Save; остальные настройки применяются сразу.

## 9.5. Сеть: работа через прокси (требование корпоративных контуров)

Приложение обязано работать там, где выход наружу возможен **только через прокси**, а VPN
запрещён. Требование касается **всех** сетевых обращений, а их три: распознавание и ИИ-правка
у Groq (§2, §6.1), скачивание локальной модели (§2.5), проверка обновлений (§10).

⚠️ **Диагноз неочевиден, и без него чинят не то.** Приложение **уже** ходит через системный
прокси: и `URLSession`, и .NET читают системные настройки сами, кода для этого не нужно.
Ломается не маршрутизация, а **авторизация**: прокси отвечает `407`, учётных данных никто не
шлёт, и снаружи это выглядит как «приложение не умеет прокси». Если прокси авторизации не
требует, всё работает и сегодня.

- **Настройка «Использовать системный прокси», по умолчанию ВКЛючена.** Выключение — ходить
  напрямую, игнорируя системные настройки. Второе тоже нужно: криво прописанный в системе
  прокси мешает не реже, чем помогает. Живёт на вкладке Network (§11.4).
- 🔀 **Механика авторизации платформенная, поведение общее.**
  - **Windows:** учётные данные текущего пользователя
    (`DefaultProxyCredentials = CredentialCache.DefaultNetworkCredentials`) — доменный SSO,
    пароль нигде не вводится.
  - **macOS:** доменного SSO для произвольного прокси нет. Пароль хранит сама система
    (Системные настройки → Сеть → Прокси, попадает в связку ключей). Приложение обязано иметь
    сессию с делегатом, чтобы подставить сохранённое и распознать отказ; **саму просьбу ввести
    пароль показывает система** — проверено на стенде: при `407` macOS сама выводит панель
    «Proxy Authentication Required» с кнопкой в Системные настройки. В приложении пароль не
    спрашивается ни в одном из вариантов.
  ⚠️ **Отличить «прокси требует пароль» от «прокси не отвечает» для HTTPS нельзя.** Обмен идёт
  методом CONNECT внутри туннеля, и наружу оба исхода выходят одной ошибкой
  (`kCFErrorDomainCFNetwork` 310). Сообщение должно годиться для обоих и называть адрес прокси:
  чинится и то и другое в одном месте. ⚠️ Домен ошибки — **CFNetwork, а не `NSURLErrorDomain`**;
  первая редакция macOS смотрела не туда и не ловила ни один живой случай.
- ⚠️ **Нужна общая точка создания HTTP-клиентов.** На macOS у `URLSession.shared` делегата не
  бывает в принципе, а на ней сидят Groq и проверка обновлений — значит ответить на `407` они
  не могут, сколько настроек ни добавляй. На Windows каждое обращение создаёт свой клиент, и
  настройка тоже применяется не ко всем. Чинить в любом случае: без общей точки требование
  выполняется частично, а это худший исход — половина функций работает, половина нет.
- **Неудача с прокси показывается человеческим сообщением** с НАЗВАННЫМ адресом прокси, а не
  общей сетевой ошибкой. В лог пишется, какой прокси разрешился для адреса: без этого разбор
  в чужой сети превращается в переписку.
  ⚠️ **Общей должна быть не только сессия, но и ТОЧКА ПЕРЕВОДА ошибки в текст.** Сессию мы
  объединили, а текст каждый вызов собирал сам — и на живом стенде вышло, что диктовка
  называла прокси по имени, а проверка ключа и проверка обновлений показывали сырое
  `kCFErrorDomainCFNetwork error 310`. Каждый новый сетевой вызов обязан звать общий перевод,
  иначе расхождение возвращается.
  ⚠️ **Текст собирается из ЛОКАЛИЗАЦИИ, а не из строк в коде.** Иначе выходит «Could not get
  through the proxy (127.0.0.1:18899 (задан приложением))» — половина фразы на чужом языке.
  В сообщение об ошибке идёт только АДРЕС; пояснение, откуда он взялся (системный / задан
  приложением / напрямую), — отдельная строка на вкладке Network.
- **Проверять прокси без корпоративной сети — заглушкой.** Дома прокси нет, а лезть в системные
  настройки сети ради теста нельзя. На macOS для этого есть `scripts/fake-proxy.py` (режимы
  «всегда 407» и «пускает по паролю») и переменная `VOICA_PROXY=host:port`, которая перебивает
  системные настройки только для запущенного процесса. Windows нужен свой такой же путь: без
  него поведение за прокси не проверяется вовсе.
  ⚠️ Заглушка окупилась сразу: поймала, что диагностика писала «напрямую» при заданном прокси,
  что детектор ошибки смотрел не в тот домен, и что человеческим текст был лишь в одном месте
  из четырёх. Ни один из трёх дефектов юнит-тестами не ловился.
- **Переключение на локальный движок не должно молча начинать скачивание.** Сегодня выбор
  «Локально (офлайн)» стартует загрузку модели немедленно (§2.5). В контуре без прокси-авторизации
  это мгновенный `407`, которого человек не просил и не понимает. Скачивание начинается по
  явному действию либо после проверки, что сеть доступна.
- ⚠️ **Ручной прокси (адрес и порт руками) — НЕ сейчас.** Записано на будущее: он означает
  хранение пароля, а значит ту же защиту, что у ключа Groq (§9) — DPAPI / файл `0600`, и
  никогда не в открытом `settings.json` или plist.
- ⚠️ **Докачка — следующий пункт, а не часть этого.** Скачивание модели идёт одним потоком без
  возобновления; сотни мегабайт через корпоративный прокси рвутся чаще, чем напрямую, и каждая
  попытка начинается с нуля. Нужна докачка (`Range` / resume data) или хотя бы честный повтор.

## 10. Проверка обновлений

- Анонимный `GET https://api.github.com/repos/<OWNER>/<REPO>/releases/latest`, заголовки
  `Accept: application/vnd.github+json` и `User-Agent: Voica`. **Каждая ОС проверяет СВОЙ репо:**
  macOS → `Inhum/voica`, Windows → `Inhum/voica-win`.
- Сравнение версий: нормализовать тег (убрать ведущее `v`), покомпонентно (`0.10.0 > 0.9.0`).
- При запуске — **не чаще раза в сутки** (кэшировать момент последней проверки); тумблер
  «Проверять при запуске» (по умолчанию вкл). Пункт меню «Проверить обновления…» — по клику.
- ⚠️ **Отказ ФОНОВОЙ проверки обязан быть тихим:** запись в лог, никаких диалогов и никаких
  повторов внутри суток. Момент проверки запоминается ДО запроса, поэтому неудача занимает
  суточное окно наравне с успехом. В закрытом контуре (§9.5) без прокси-авторизации проверка
  падает при каждом запуске, и болтливость здесь превращается в поток бессмысленных окон.
  Ручная проверка, наоборот, обязана показать ошибку: её попросили.
- Если версия новее — предложить открыть **страницу релиза** (пункт меню меняется на «Скачать
  обновление X.Y.Z», алерт при ручной проверке). **Никогда не качает/не ставит сам.**
- **Место в UI (macOS 0.9.9):** проверка обновлений живёт во **вкладке About** (кнопка
  «Проверить обновления» со статусом + «Скачать» при наличии новой + тумблер «проверять при
  запуске»). Пункт меню «Проверить обновления…» сохранён. См. §11.5.

## 11.3. Первый запуск
- **Первый запуск без ключа не должен быть тупиком (macOS 0.9.17).** Если ключа нет, приложение
  открывает настройки с курсором в поле ключа — и человек читает это как «без ключа никак»,
  хотя локальный движок §2.5 не требует ни ключа, ни интернета. Под кнопками сохранения ключа
  показывается строка: «Ключа нет? Он нужен только облачному движку. Переключите распознавание
  на "Локально (офлайн)" выше — оно работает без ключа и без интернета.»
  - Видна **только** когда выбран облачный движок И ключа нет. Есть ключ — облако работает;
    выбран локальный — ключ не нужен.
  - Пересчитывается при открытии настроек, смене движка и сразу после сохранения ключа.
  - **Обычным цветом текста, а не блёклым**: рядом три серые подсказки, четвёртая такая же
    потерялась бы, и смысл пропал.
  - Ставится под полем ключа, а НЕ у переключателя движка: на первом запуске курсор стоит в
    поле ключа, туда и смотрит человек — там же у него возникает ощущение тупика.
  ⚠️ Кнопки-действия у строки намеренно нет: переключатель движка стоит выше и виден, а кнопка
  провоцировала бы скачать 400 МБ раньше, чем человек поймёт, зачем.

## 11.4. Окно настроек: вкладки и размер


- Настройки — **окно с вкладками** (`General / Dictation / Vocabulary / Data / Network / About`),
  переключение иконками сверху; на macOS — стиль системных настроек (toolbar-style).
- **Вкладка Network — перед About.** Содержит настройку системного прокси (§9.5). Заведена
  сразу на обеих платформах: шестая вкладка в одиночку развела бы их на ровном месте. Задел на
  ручной прокси в будущем — он ляжет туда же.
- **Высота окна подгоняется под выбранную вкладку** (macOS 0.9.11), и это двусторонне:
  окно и растёт под более высокую вкладку, и **ужимается** под более низкую. Проверять надо
  оба направления и **первый показ**: если окно открывается сразу на конкретной вкладке
  (пункт меню «О программе» ведёт на About), размер должен соответствовать именно ей.
- **Грабли macOS (зафиксировать):** штатный `NSTabViewController` растит окно, но обратно не
  ужимает, а на первом показе не применяет размер выбранной до показа вкладки. Через
  `preferredContentSize` не лечится — к моменту показа там уже нужное значение, и присвоение
  того же самого ничего не меняет. Рабочий путь: сдвигать рамку окна самим на разницу
  «нужно минус занято», при каждом переключении вкладки и после показа окна.
- Инлайн-подсказки, которые не влезают, выносятся в **иконку ⓘ** с поповером по наведению —
  иначе вкладка перестаёт помещаться в окно.
- ⚠️ **Длинный текст в строке состояния НЕ должен менять размер окна.** Строки статуса (движок,
  ключ, обновления) получают текст ошибки, а он бывает длинным: сообщение о прокси растянуло
  окно настроек в полтора раза. Ограничение ширины плюс перенос по словам — сразу у всех строк
  состояния, а не у той, где это заметили.
- ⚠️ **Одинаковые предупреждения не наслаиваются.** В режиме PTT каждое нажатие клавиши
  начинает диктовку, поэтому пара нажатий подряд давала два одинаковых окна друг на друге.
  Если окно уже открыто — поднимать его, а не открывать второе.

## 12. Локализация, версия, приватность, самотест

- **UI на английском и русском**, по языку системы.
- **Версия** читается из бандла/сборки (единый источник правды), semver.
- **Приватность:** нет бэкенда, нет телеметрии. Сеть только к `api.groq.com` (облачная
  транскрибация и/или ИИ-исправление) и `api.github.com` (опциональная проверка обновлений;
  плюс разовая докачка локальной модели из release-ассета, §2.5). При **локальном** движке
  без ИИ-исправления аудио и текст **никуда не уходят** — обработка целиком на устройстве.
- **Самотест** без сети/GUI (напр. флаг `--test-all`), покрывает чистую логику: сравнение
  версий, подготовку `prompt` из словаря, round-trip хранилища ключа и настроек, insert/delete
  истории, маппинг клавиш, конкурентный доступ к БД. Восстанавливает изменённое состояние.
- **Диагностические флаги (macOS, кроме `--test-all`).** Держать документированными: без списка
  они находятся только чтением `main.swift`.
  - `--normalize-corpus <файл>` — прогон правил §6.2–§6.4 по строкам файла, печатает только
    изменившееся (методика §6.2). Уважает выключатели §6.5.
  - `--notify-test` — статус разрешения на уведомления + пробный баннер.
  - `--transcribe <файл>` — распознать готовый аудиофайл.
  - `--print-prompt <словарь> <текст>` — показать промпт ИИ-исправления.

## 13. Выпуск: кандидаты в релиз

Правило введено 2026-08-26, после периода, когда релиз выпускался на каждую фичу и каждую
починку. Цена такого темпа: непроверенное уезжает всем пользователям, а проверка превращается
в поток релизов, от которого устаёт в первую очередь тот, кто их выпускает.

- **Всё, что видно пользователю, идёт сначала кандидатом.** Тег `vX.Y.Z-rc.N`, релиз
  публикуется как **pre-release**.
- **Почему именно pre-release, а не сборка руками.** GitHub не отдаёт pre-release в
  `/releases/latest`, а проверка обновлений (§10) ходит именно туда — значит кандидат не
  виден обычным пользователям и пункт «Скачать обновление» им не загорается. При этом артефакт
  собран тем же CI, что и релиз, у него постоянная ссылка, и через неделю на вопрос «какая у
  тебя версия» есть ответ. Сборка с ноутбука не даёт ни того, ни другого.
- **Цикл:** кандидат → проверка на своей машине → проверка у живого пользователя → починка →
  следующий кандидат `rc.N+1` на той же базовой версии. Когда претензий не осталось — тег
  `vX.Y.Z` без суффикса, и он становится `latest`.
- **Версия в Info.plist всё это время равна `X.Y.Z`**: суффикс живёт только в теге. Поэтому
  проверенный кандидат выпускается тем же кодом, без пересборки смысла.
- **Отдельная ветка не нужна.** Кандидат режется тегом с main; ветка добавляет слияния и
  ничего не решает, пока main остаётся выпускаемым.
- ⚠️ **Кандидат обязан ПОКАЗЫВАТЬ, что он кандидат.** В About стоит полная версия с суффиксом
  (`0.9.19-rc.1`), иначе `rc.1`, `rc.2` и финал выглядят одинаково и тестировщик не может
  ответить, что у него стоит, — а ради этого ответа кандидаты и заведены. В репозитории версия
  остаётся базовой; суффикс штампует CI при сборке по тегу, после сверки версии.
  ⚠️ **Тогда же обязано быть исправлено сравнение версий:** разбор по точкам на строке
  `0.9.19-rc.1` превращает `19-rc` в ноль, и приложение предлагает тестировщику «обновиться»
  на предыдущий выпуск. Суффикс отбрасывается перед разбором, а при равных числах **выпуск
  считается новее своего кандидата** — иначе тестировщик не узнает, что вышел финал.
- ⚠️ **CI обязан отличать кандидата от релиза.** На macOS это стоило отдельной правки: сверка
  версии сравнивала тег с Info.plist целиком и падала на суффиксе, имя dmg и раздел CHANGELOG
  тоже искались по полной строке с суффиксом. Суффикс отсекается для всего, кроме заголовка
  релиза. Windows-порт обязан проверить своё то же самое ДО первого rc-тега.
